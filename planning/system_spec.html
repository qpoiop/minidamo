1. 폴더 아키텍처 & 배포 단위

프론트엔드는 vite-plugin-pwa의 injectManifest 전략으로 Workbox 프리캐시 매니페스트를 커스텀 서비스 워커(src/sw.ts)에 자동 주입한다. 시그널링/TURN 발급은 프론트엔드와 완전히 분리된 배포 단위인 Cloudflare Worker(worker/, 별도 wrangler deploy)가 전담한다 — 라이브러리는 PeerJS가 아니라 순수 RTCPeerConnection 래퍼(src/services/rtc.ts)다.

2. GPS 기반 근거리 매칭 프로토콜 규격

Cloudflare Worker(/rooms)는 활성 방 목록에 각 호스트의 좌표를 그대로 담아 반환할 뿐 거리 필터링은 하지 않는다 — 실제 20m 반경 필터는 클라이언트(useRoom.ts의 searchNearbyRooms)가 자신의 좌표와 각 방 좌표 사이 거리를 하버사인 공식으로 계산해 수행한다. VITE_SIGNALING_URL이 비어 있으면 시그널링 자체가 비활성화되어 QR 코드/4자리 코드 오프라인 교환으로만 방 참가가 가능하다.

방 요약 구조체 (실제 응답 스키마)

// GET /rooms 응답 — worker/src/index.ts
interface RoomSummary {
  roomId: string;
  hostName?: string;
  gameId?: string;
  location?: { lat: number; lon: number; acc: number };
  createdAt: number;
  expiresAt: number;

반경 연산 공식 (Haversine, 클라이언트 실행)

src/utils/distance.ts의 getDistance() — Worker가 아니라 브라우저에서 매 /rooms 조회 시 실행되며, NEARBY_RADIUS_M = 20m 이내만 nearbyRooms에 남긴다.

// getDistance() — src/utils/distance.ts
const R = 6371e3; // 지구 반경 (미터)
const phi1 = lat1 * Math.PI/180;
const phi2 = lat2 * Math.PI/180;
const deltaPhi = (lat2-lat1) * Math.PI/180;
const deltaLambda = (lon2-lon1) * Math.PI/180;

const a = Math.sin(deltaPhi/2) * Math.sin(deltaPhi/2) +
          Math.cos(phi1) * Math.cos(phi2) *
          Math.sin(deltaLambda/2) * Math.sin(deltaLambda/2);
const c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1-a));

const distance = R * c; // 계산된 최종 거리 (미터 단위)

3. WebRTC 연결 · TURN · 재연결 프로토콜 규격

ICE 서버 풀은 STUN(Google×5·Cloudflare·Twilio) + 공개 오픈릴레이 TURN을 기본으로 하고, Cloudflare Worker의 /turn-credentials에서 발급하는 Cloudflare Realtime TURN 자격증명을 런타임에 병합한다(buildIceConfigWithTurn(), 발급 실패 시 정적 풀로 자동 폴백). 상세 발급/할당량 정책은 planning/TURN_SETUP.md 참조.

// 실제 P2P 메시지 유형 — src/hooks/useRoom.ts
type P2PMessage = {
  type: 'LOBBY_STATE' | 'GAME_START' | 'GAME_ACTION' | 'GAME_RESET'
      | 'HEARTBEAT' | 'HEARTBEAT_ACK' | 'GPS_UPDATE' | 'DISCONNECT' | 'CHAT';
  senderId: string;
  timestamp: number;
  // payload는 20+ optional 필드를 가진 넓은 유니온(위치/플레이어 목록/
  // 게임별 액션 필드 등) — 신규 게임 4종은 자유 필드 gameData?: unknown
  // 로 자체 프로토콜을 태움. 전체 필드는 useRoom.ts 참조.
  payload: Record;
}

const HEARTBEAT_INTERVAL_MS = 2000   // 2초마다 HEARTBEAT ↔ HEARTBEAT_ACK
const CONNECTION_LOSS_MS = 6500      // 응답 없으면 연결 끊김으로 간주
const RECONNECT_WINDOW_S = 180       // 3분 — iOS/Android 백그라운드 억제 대응
const JOIN_CONNECT_TIMEOUT_MS = 20_000

하트비트 & 진단

  • 2초마다 HEARTBEAT/HEARTBEAT_ACK 교환, 6.5초 무응답 시 연결 끊김 판정.
  • ICE candidate 타입(host/srflx/prflx/relay)과 연결 상태를 DiagPanel로 화면에 노출(모바일 콘솔 접근 불가 대응) — GPS/RTT 임계값 기반 경고 배너는 존재하지 않음. distance/rtt state는 계산만 되고 어떤 UI에도 소비되지 않는 죽은 값(별개로 로비의 근거리 방 표시용 NearbyRoom.distance는 실사용).

세션 재수립 동작

  • 트리거는 GPS/RTT가 아니라 ICE 상태(disconnected/failed) · DataChannel close · 하트비트 무응답.
  • 180초 재접속 창 만료 시 connectionStatus만 IDLE로 전환 — 화면 자동 전환은 없고 사용자가 재접속 시도/방 나가기를 직접 선택.

4. 서비스 워커 (PWA) 명세

src/sw.ts — 하드코딩 캐시 목록이 아니라 vite-plugin-pwa가 빌드 시 주입하는 self.__WB_MANIFEST를 Workbox precacheAndRoute()로 프리캐시한다. cleanupOutdatedCaches()는 자체 activate 리스너를 등록하는 방식이라 모듈 최상단(동기)에서 호출해야 하며, 이전 버전 SW가 남긴 precache 버킷만 정리하고 런타임 캐시는 건드리지 않는다(전체 캐시 무효화 금지 — ROADMAP 하드 룰).

등록된 리스너

  • message — SKIP_WAITING 수신 시 self.skipWaiting()(PWAPrompt 업데이트 버튼과 연동).
  • activate — clients.claim()만 수행.
  • push / notificationclick — 알림 표시 및 클릭 시 창 포커스/오픈. 실제로 존재하지만 클라이언트 어디에도 PushManager.subscribe/권한 요청 UI가 없어 발신 경로가 없는 준비 단계 코드(미연동).

매니페스트

  • 정적 manifest.json 없음 — vite.config.ts의 VitePWA({ manifest: {...} })가 빌드 시 생성.
  • name/short_name: minidamo, display: standalone, registerType: prompt(자동이 아니라 업데이트 프롬프트 노출 후 사용자 확인).

5. CI/CD 배포 파이프라인 (GitHub Actions)

워크플로는 .github/workflows/deploy.yml 단 하나 — 별도 lint/test 전용 워크플로는 없다. production 브랜치 push 시에만 트리거되어 프론트엔드를 Cloudflare Pages에 배포한다. 시그널링/TURN Worker(worker/)는 이 워크플로에 포함되지 않고 npx wrangler deploy로 별도 수동 배포한다.

// .github/workflows/deploy.yml 요약
on: push → branches: [production]

steps:
  - checkout
  - setup-node (22)
  - npm ci
  - npm run lint     # 실제로는 ESLint가 아니라 tsc --noEmit (타입 체크)
  - npm run build    # tsc -b && vite build
      env: VITE_SIGNALING_URL, VITE_TURN_URL,
           VITE_TURN_USERNAME, VITE_TURN_CREDENTIAL (secrets)
  - cloudflare/pages-action@v1
      projectName: minidamo · directory: dist · branch: production
