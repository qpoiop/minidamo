1. 서비스 개요

minidamo는 모바일 PWA(Progressive Web App)를 기반으로 한 2인용 근거리 P2P 미니게임 플랫폼입니다. 앱 스토어를 통하지 않고 즉시 홈 화면에 웹앱 형태로 추가해 오프라인 캐싱 및 백그라운드 웹 푸시 알림을 지원받아 설치형 네이티브 앱과 동일한 유저 플로우를 완성합니다.

핵심 비전: "GPS 근거리 방 탐색으로 상대방과 탭 한 번에 매칭되고 끊김 없는 실시간 미니게임을 보장하는 모바일 PWA 서비스"

Target User

  • 현실에서 마주 앉아 가벼운 내기나 오락을 원하는 사용자 (친구, 연인, 동료)
  • 설치형 게임 앱 다운로드 및 업데이트가 귀찮은 모바일 라이트 유저
  • 오프라인이나 불안정한 모바일 기기 네트워크 환경에서도 끊김 없는 연결을 원하는 사용자

Core Value

  • 네이티브 앱급 접근: PWA 추가 설치 지원, 서비스 워커 캐싱
  • 서버 부하 최소화: WebRTC P2P 직송 기반의 초저지연 상태 관리
  • 지능형 근거리 탐색: 위도/경도 연산 필터링으로 20m 이내 매칭 구현
  • 다중 매칭 경로: GPS 20m 반경 탐색이 기본, JOIN 화면에는 QR 스캔·4자리 방 코드 수동 입력도 상시 대안으로 함께 제공

2. 근거리 매칭(GPS/QR/코드) 및 P2P 연결·재접속 정책

브라우저 Sandbox 보안 규정상 블루투스 직접 스캔 등이 제한되므로, Geolocation API(위도/경도)를 기본 매칭 경로로 사용합니다. JOIN 화면에는 QR 코드 스캔·4자리 방 코드 수동 입력도 사용자가 언제든 직접 선택할 수 있는 대안으로 함께 제공됩니다(자동 전환이 아닌 상시 노출 UI).

1

방 개설 및 GPS 좌표 등록 (Host)

호스트가 게임 방을 개설하면 브라우저 GPS로 현재 위도/경도를 조회하여 호스트의 Peer ID와 함께 Cloudflare Worker 시그널링 서버에 일시 전송합니다(시그널링 서버 자체가 없거나 오프라인이면 GPS 매칭 UI 대신 QR 코드/4자리 코드 경로를 사용).

2

주변 20m 이내 방 필터링 (Guest)

게스트가 "주변 참가" 버튼을 누르면 게스트의 현재 위도/경도를 전송하고, 서버는 하버사인 공식(Haversine Formula)을 사용해 반경 20m 이내 방 목록만 추려서 보여줍니다.

3

탭 매칭 및 WebRTC 연결

게스트가 목록에서 방을 터치하면 서버가 두 피어의 ID를 기반으로 핸드셰이크를 처리하고, 다이렉트 WebRTC DataChannel을 열어 direct P2P 망을 활성화합니다. STUN으로 직접 연결이 안 되면 별도 Worker가 프록시하는 Cloudflare Realtime TURN 자격 증명으로 중계 연결을 시도합니다.

4

연결 상태 감시 및 재접속 정책

GPS 거리·WebRTC RTT는 내부적으로 계속 계산되지만 현재 UI 경고에는 노출되지 않습니다. 대신 하트비트(HEARTBEAT/ACK) 응답 유무와 WebRTC 연결 상태(ICE disconnected/failed, DataChannel 종료)를 기준으로 상대 이탈을 감지해 다음과 같이 대응합니다.

🔌 연결 이상 감지

다음 조건 중 하나라도 발생하면 재접속(RECONNECTING) 상태로 전환됩니다:

  • WebRTC ICE 상태가 disconnected/failed 로 전이.
  • DataChannel 이 예기치 않게 close.
  • 정기 하트비트에 대한 응답이 일정 시간 없음.
  • 탭이 백그라운드로 전환되면 재접속 카운트다운을 일시 정지해 화면 잠금·앱 전환으로 인한 오탐을 방지.

🛑 재접속 대기 및 만료

재접속 상태 진입 시:

  • 스피너와 함께 180초(3분) 카운트다운 팝업 노출 — 상대측 이탈이면 "상대방 연결 끊김", 내 기기 오프라인이면 "네트워크 연결 끊김" 문구로 구분.
  • 180초 안에 하트비트가 복구되면 자동으로 정상 연결 상태로 복귀, 기존 스코어와 진행 상태 그대로 이어서 재개.
  • 180초를 초과하면 팝업에 "상대방과 재연결할 수 없어요" 오류가 표시되며, 사용자가 재접속 시도 또는 방 나가기(메인으로 이동)를 직접 선택. 자동으로 화면이 전환되지는 않음.

3. PWA (Progressive Web App) 스펙 및 푸시 알림 정책

설치 가능성, 업데이트 신속성, 사용자 리인게이지먼트를 위해 설계된 PWA 세부 정책입니다.

설치 및 디스플레이 (Manifest)

  • 설치 유도 카드: beforeinstallprompt 이벤트 발생 시 플로팅 카드로 "앱 홈 화면에 추가"를 노출. iOS Safari는 이 이벤트를 지원하지 않아 공유 → 홈 화면에 추가 수동 안내 카드를 별도로 보여줌.
  • 디스플레이 모드: standalone 설정으로 브라우저 주소창, 뒤로가기 버튼 등을 감춰 풀스크린 앱처럼 노출.
  • 오프라인 준비 알림: 최초 프리캐싱이 끝나면 "오프라인 준비 완료 · 네트워크 없이도 실행 가능" 토스트로 안내.

서비스 워커 & 캐시 라이프사이클

  • 정적 프리캐싱: workbox precacheAndRoute로 빌드 산출물(JS/CSS/게임 에셋)을 설치 시점에 전량 캐싱해 오프라인에서도 작동 보장. 별도 런타임 캐싱(API·이미지) 규칙은 없음.
  • 무중단 업데이트: 새 배포가 감지되면 "새 버전 배포 · 업데이트 후 적용" 카드 노출. "업데이트" 터치 시 즉시 릴로드 적용(응답이 없으면 4초 후 강제 새로고침으로 폴백).

웹 푸시 알림 (Web Push Notification) — 준비 단계: Service Worker에 push/notificationclick 리스너는 구현되어 있어 서버가 푸시를 보내면 "초대 알림" 등을 백그라운드 상태에서도 수신할 수 있는 기반은 갖춰져 있습니다. 다만 현재 클라이언트에는 PushManager.subscribe() 구독 흐름이나 알림 권한 요청 UI가 없어, 실제로 푸시를 발신하는 경로는 아직 연결되어 있지 않습니다(후속 사이클 후보).

4. 수록 미니게임 개요

총 10종 미니게임을 수록하며, 장르(전략/추리/협동)와 진행 방식(턴제/실시간)으로 분류됩니다. 개별 게임의 상세 룰은 인게임 각 게임 가이드(카드 모달)에서 확인할 수 있어, 이 문서는 진행 방식별 대표 사례 2종만 개요로 다룹니다.

1. 룰셋 판도라 (BombHunt) — 턴제 그리드 대표

  • 보드: 3×3(기본)/4×4/5×5 중 선택하는 N×N 그리드.
  • 진행 방식: 턴제 교대 — 매 턴 카드 열람·힌트 조회·폭탄 지목 중 하나를 수행.
  • 승리 조건: 폭탄을 정확히 지목한 쪽 승리. 상대가 폭탄을 뒤집거나 오답 지목해도 승리.
  • P2P 연동: 호스트가 보드 시드를 생성하고, 이후 각자 액션(카드 열람/폭탄 지목)을 P2P 메시지로 교환해 두 화면의 보드 상태를 동일하게 유지.

2. 협동 미로 (Escape) — 실시간 캔버스 대표

  • 경기장 Layout: 원형 시야 + 안개 처리된 캔버스 미로, 원형 조이스틱으로 이동.
  • 진행 방식: 실시간 — 두 명이 서로 다른 지점에서 시작해 열쇠 획득 후 각자 출구에 도달해야 팀 성공.
  • 승리 조건: 두 사람 모두 출구를 밟아야 성공. 한 명만 먼저 도착하면 상대를 기다리는 관전 모드로 전환.
  • P2P 연동: 위치·아이템 상태를 주기적으로 브로드캐스트해 두 화면을 동기화. 매치 타이머 만료도 먼저 감지한 쪽이 브로드캐스트해 host/guest 간 판정 편차를 제거.
