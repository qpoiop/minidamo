## 서킷 브레이커 9종 — 발동 매트릭스

| ID | 이름 | 발동 조건 | 결과 |
|----|------|-----------|------|
| CB-1 | 개발 루프 | B 재시작 3회 | A 강제 복귀 |
| CB-2 | 동일 실패 패턴 | 같은 이유 2회 연속 | A 에스컬레이션 |
| CB-3 | 스코프 드리프트 | 초기 대비 30%+ 증가 | 범위 재조정 |
| CB-4 | 기획 모순 | 구현 불가 스펙 | 즉시 A 복귀 |
| CB-5 | 오버엔지니어링 | 불필요한 복잡도 | 단순화 지시 |
| **CB-7** | **시간 예산 초과** | 사이클 wall-clock 100% | 사이클 분할 |
| **CB-8** | **호출 예산 초과** | 단계 tool-call 100% | 부분 인계 |
| **CB-9** | **Veto 반복** | 동일 V 트리거 3회 | **사용자 에스컬레이션** |
| CB-6 | HALT | 누적 한계 / 환경 문제 | 시스템 정지 |

---

## CB-1: 개발 루프 브레이커

**발동**: 동일 사이클 B 재시작 3회+

```json
state.current_cycle_state.b_restart_count >= 3
```

**PM 액션**:
- 스펙 불명확 → A 강제 복귀, 스펙 재작성
- 기술 제약 → PM이 제약 스펙 명시 후 재개발
- 환경 문제 → HALT

---

## CB-2: 동일 실패 패턴 브레이커

**발동**: 같은 실패 이유 2회 연속

**감지**:
- 동일 `npm run lint` 에러 반복
- 동일 V 트리거 반복
- 동일 빌드 실패 원인 반복

---

## CB-3: 스코프 드리프트 브레이커

**발동**: 작업 범위가 초기 스펙 대비 30%+ 증가

minidamo 감지:
- View 수정 스펙 ➔ Context/Hook 구조 변경 및 파일 과다 수정으로 확대
- 버그 수정 ➔ 새 기능 추가로 확대

---

## CB-4: 기획 모순 브레이커

**발동**: CLAUDE.md 아키텍처 원칙과 충돌하는 스펙 발견

minidamo 예시:
- "View에서 직접 데이터를 제어하도록 우회" 스펙
- `usePeer.ts` 및 `useLocation.ts`를 거치지 않고 개별 상태 훅 남발 요구

---

## CB-5: 오버엔지니어링 브레이커

**발동**: 현재 서비스 단계 대비 과도하다고 PM/검토 에이전트 판단

minidamo 예시:
- 단순 목록 표시에 과도하게 복잡한 다중 하위 컴포넌트 분할 및 불필요한 State Context 남발
- 백업 서버 연동 전인데 복잡한 데이터 동기화 계층 전체 설계

---

## CB-7: 시간 예산 초과 브레이커

**발동**: 사이클 wall-clock 100% 도달

**PM 액션**:
1. 진행 중 에이전트 안전한 중단점에서 종료
2. 미완 항목 TODO.md 추가, 다음 사이클 이월
3. pm-decision.md에 분할 결정 기록

---

## CB-8: 호출 예산 초과 브레이커

**발동**: 단일 에이전트 tool-call 자체 한도 100% 도달

**감지 안티패턴**:
- 동일 파일 5회+ 재읽기 ("Re-read storm")
- `npm run lint` 변경 없이 반복 실행

---

## CB-9: Veto 반복 브레이커

**발동**: 동일 사이클 내 같은 V 트리거 3회+ 연속

**PM 액션**:
1. **사용자 에스컬레이션** 모드 전환
2. state.json `status` → `awaiting_user_intervention`
3. pm-decision.md에 반복 트리거, 개발자 시도, 해결 경로 후보 기록

minidamo 예시:
```
서킷 브레이커 발동: CB-9 (Veto 반복)
트리거: V1 (Hardcoding) — 동일 사이클에서 3회 발동
위치: src/features/home/Home.tsx (색상코드 직접 사용)
개발자 시도: 인라인 헥사 코드 교체 시도했으나 CSS 변수 미사용으로 반복

가능한 해결 경로:
1. CSS Custom Properties 사용 방법을 스펙에 명시 후 재개발
2. 해당 스타일을 src/components/common/ 공통 스타일이나 variables.css로 이동하여 표준화
3. P1 Severity를 이 특정 케이스에서 SHOULD로 낮춤 (사용자 권한 필요)
```

---

## CB-6: 시스템 정지 (HALT)

**발동**: 다음 중 하나
- 총 B 재시작 5회 초과
- README.md / TODO.md 부재 또는 읽기 불가
- `node` 및 `npm` 명령어 없는 환경
- 동일 사이클 서킷 브레이커 3개+ 발동
- 일일 예산 100% + 핵심 기능 미완성
- github_pat 등 시크릿 소스 노출 감지 → 즉시 HALT

**PM 액션**: state.json status = "halted" + 상세 기록

## 에스컬레이션 흐름

```
이슈 발견 (어느 에이전트든)
  └─► PM에 보고
        └─► PM 분석
              ├── 단순 수정 → 재작업 지시
              ├── 기획 문제 → A 복귀 (CB-1, CB-4)
              ├── 범위 문제 → 범위 재조정 (CB-3)
              ├── 품질 문제 → 단순화 (CB-5)
              ├── 비용 문제 → 분할/부분 인계 (CB-7, CB-8)
              ├── 거부권 반복 → 사용자 에스컬레이션 (CB-9)
              └── HALT 조건 → 시스템 정지 (CB-6)
```

## 다중 발동 처리

| 우선순위 | CB | 처리 |
|---------|-----|------|
| 1 | CB-6 (HALT) | 다른 CB 무시, 즉시 정지 |
| 2 | CB-9 (Veto 반복) | 사용자 에스컬레이션 |
| 3 | CB-4 (기획 모순) | 즉시 A 복귀 |
| 4 | CB-7, CB-8 (예산) | 분할/부분 인계 |
| 5 | CB-1, CB-2 (루프/실패) | A 복귀 또는 단순화 |
| 6 | CB-3, CB-5 (범위/오버엔지) | 범위 조정 |

3개+ 동시 발동 → 자동 CB-6 (HALT) 격상.
